# Ludotheca

Проверяемая энциклопедия игр и игровых механик, описанных в литературе, мифологии и фольклоре.

## Принципы

- Только факты из конкретных текстов и редакций. Никакой реконструкции или вымышленных правил.
- Одно произведение за один проход; регистрировать даже произведения без подходящих игр.
- Для каждого свидетельства указывать оригинальное `work_title` и при наличии подтверждённого перевода `work_title_ru`; место в оригинале — `source.location`, русское редакционное обозначение главы — `source.location_ru`. Не подменять оригинал переводом и не выдавать редакционный перевод за цитату.
- На сайте показывать русское название произведения и главы первым, оригинал — рядом; отделять наблюдения за игрой от явно сформулированных правил.
- В поле `name` записывать основное русскоязычное название игры; в `original_name` — название на языке первоисточника, если оно прямо присутствует в тексте. Не выдумывать оригинальное название при его отсутствии.
- `name_is_editorial: true` означает, что русскоязычное название предложено редактором, а не засвидетельствовано как устойчивое название игры. Перевод оригинального названия тоже помечать как редакционный, если нет подтверждённого принятого русского названия.
- Название в первоисточнике необязательно, если описано конкретное игровое действие, правило, цель или механика. В таком случае дать нейтральное русское редакционное название и не заполнять `original_name`.
- Одного названия, факта игры или количества участников недостаточно.
- Наличие цели, срока, награды, наказания или условия успеха само по себе не делает событие игрой. Сказочные поручения, подвиги, брачные испытания и проверки выносливости без самостоятельного игрового процесса исключаются.
- Для включения требуется описанный игровой процесс: участники совершают действия в рамках игры, головоломки или состязания по специфическим игровым правилам. Отличать игровой выбор и повторяемые игровые действия от разового сюжетного препятствия.
- Общеизвестные традиционные игры включать только при доказанном отличии правил или необычной механике; сравнение подтверждать источником.
- Не смешивать варианты одной игры: одна общая карточка, отдельные свидетельства для каждого произведения.
- `added_at` неизменен после первого добавления, `updated_at` меняется при содержательной правке.
- Нет прототипов, идей адаптации и оценок цифровой реализации.

## Структура

- `data/games/*.yaml` — единая карточка игры и отдельные свидетельства по произведениям.
- `data/games/index.json` — список путей карточек для сайта.
- `data/processed-works.yaml` — реестр исследованных произведений, включая нулевые результаты.
- `schema/game.schema.json` — проверяемая схема карточки.
- `schema/processed-works.schema.json` — схема реестра.
- `index.html`, `app.js`, `styles.css` — статический каталог.

## Добавление

1. Выбрать ещё не обработанное произведение и конкретную доступную редакцию.
2. Прочитать первоисточник, извлечь все игры, отвечающие критериям.
3. Проверить существующие `id` игр и добавить новое свидетельство либо новую карточку.
4. Указать место в тексте и ссылку, отделяя действия персонажей от универсальных правил.
5. Обновить реестр и даты; открыть один Pull Request.

Сайт использует js-yaml через CDN для чтения YAML; при отсутствии сети загрузка данных может быть недоступна.
